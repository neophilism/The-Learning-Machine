# Canonical PR Registry Contract

`registry/prs.json` is the sole planning graph and contains 96 stable work-unit IDs. An ID is never a GitHub PR number. Each item provides `id`, `phase`, `title`, `depends_on`, `scope`, two explicit `acceptance_criteria`, `status`, actual `github_pr_number`/`github_pr_url` when known, `merged_commit`, and `verification_evidence`. Valid statuses: planned, in_progress, in_review, blocked, merged, superseded. Merged status requires exact GitHub merge SHA and passing acceptance evidence. No partially implemented unit may be marked merged or completed; code and docs must match the entire acceptance scope. A superseded unit requires an identified fully tested replacement. Dependencies must exist and be strictly predecessor-only; registry checker rejects cycles/gaps and impossible states. Remaining PR counts count genuine unmerged scope, not fictional partials.
